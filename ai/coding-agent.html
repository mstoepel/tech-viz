A coding agent is the loop plus three habits: read, edit, verify

Give an agent a repo and a failing test. Every good run has the same shape: reproduce the failure, read only what the failure points at, make one edit, run the tests again, and stop when they pass. Every bad run is one of those steps missing. Pick a strategy, step the loop, and watch which files it reads, what it costs, and whether the green bar was earned or claimed.

Engine notes. Same shell as the agent loop page. The repo is seven files with real contents; the test harness actually computes the cart total from whatever the edited file says, so a wrong edit produces a real wrong number. The "model" is a scripted policy per strategy — careful, blind, greedy, no-verify — because the point is the loop around it, not its judgement. Tool results cost what they'd cost: a file read costs the file. The subagent runs its own loop in its own context and hands back a summary; the parent pays only for the summary.
