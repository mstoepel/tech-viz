Sandbox 02 · Containers

localhost means a different machine depending on where you're standing

Every container gets its own network namespace: its own interfaces, its own IP, its own loopback. Reaching anything outside that namespace is either a route across a network you both sit on, or a port punched through the host. Start containers, try connections from different places, and read exactly where each one dies.

Engine notes. Same shell as the other sandboxes. A connection attempt is a pure function of the topology: resolve the name in the caller's namespace (loopback, the embedded DNS of a shared user-defined network, or the host's aliases), pick a route (same network, a published port DNAT'd through the host, or nothing), then check what is actually listening and on which address. Images come with a default listening port (nginx 80, api 3000, postgres 5432, redis 6379, metrics-agent 9100). Reaching container IPs directly from the host is flagged as Linux-only, because that is the portability trap it is.
