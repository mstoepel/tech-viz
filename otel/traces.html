Sandbox 01 · Observability

A trace is one id, carried in a header, that nobody is allowed to drop

Three services handle one request. Each records what it did as spans. The only thing that turns those spans into a single trace is a tiny header each service must forward to the next. Send requests, break the chain in different places, and watch what the tracing backend would show you.

Engine notes. Same shell as the other sandboxes. A request is simulated as a recursive call down the chain; each service, if it has an SDK, opens a server span, an internal span for its own work, and a client span for the outgoing call, and forwards a W3C traceparent header only if it is configured to. Sampling is head-based: the root decides, the flag rides in the header. Timings are illustrative.
