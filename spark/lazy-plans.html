Sandbox 01 · Data engineering

Nothing runs until you ask. Then everything runs at once

A PySpark DataFrame is not data. It's a description of how to get data, and every method call makes the description longer. Only an action — show, count, write — hands it to the engine, which rewrites it, plans it, cuts it into stages, and finally reads a file. Type the code and watch the plan; then ask, and watch what the engine does to it.

df = events.filter("country = 'DE'") · df = df.join(users, "user_id") · df = df.groupBy("plan").agg(sum("value")) · df.explain() · df.show() · conf shuffle.partitions 8 · conf autoBroadcast off · help

Engine notes. Same shell as the other sandboxes, with a Python-flavoured prompt. The plan is a real tree with estimated row counts; the optimizer is four of Catalyst's hundreds of rules (combine filters, push predicates down, prune columns, collapse projections), applied in order and recorded as before/after; the physical planner inserts a shuffle exchange under every aggregate and sort-merge join and a broadcast exchange under a small join side, then cuts stages at the exchanges and counts one task per partition. Row estimates use fixed selectivities. Two tables: events (1M rows, 8 partitions, 512 MB) and users (50k rows, 4 partitions, 6 MB, small enough to broadcast).
