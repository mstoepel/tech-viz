Kubernetes never does what you say. It closes a gap

kubectl writes a wish into a database. Separately, a handful of loops wake up, compare that wish with what actually exists, and each fix one small difference. Type commands, then tick to let the loops run, and watch the gap close.

Engine notes. Same shell as the git and docker sandboxes. The one new idea is that kubectl reducers only edit state.deployment; every other field is touched only by reconcile(), which runs each controller once per tick in a fixed order. Rollouts use maxSurge 1, maxUnavailable 0. There is no etcd, no API latency, no probes — just the loop.
